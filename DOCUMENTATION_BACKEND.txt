1. VUE D'ENSEMBLE DU BACKEND
=============================

Le backend Transcendence est une API REST construite avec Spring Boot qui gère:
- L'authentification des utilisateurs (inscription, connexion)
- Génération et validation des JWT tokens
- Gestion des utilisateurs et leurs données
- Protection des ressources via JWT
- Communication sécurisée avec le frontend

TECHNOLOGIES UTILISÉES:
=======================
- Spring Boot 3.x: Framework web et configuration automatique
- Spring Security: Authentification et autorisation
- Spring Data JPA: Accès à la base de données
- JWT (JSON Web Tokens): Tokens d'authentification sans état
- Maven: Gestion des dépendances et build
- Java 17+: Langage de programmation
- MySQL/PostgreSQL: Base de données (optionnel en dev)
- H2 Database: Base de données en mémoire pour les tests (optionnel)

B) AuthController.java
──────────────────────
Gère les endpoints d'authentification.

Endpoints exposés:
- POST /auth/login      → connexion utilisateur
- POST /auth/register   → inscription nouvel utilisateur

Code type:

@RestController
@RequestMapping("/auth")
public class AuthController {
    
    @Autowired
    private AuthService authService;
    
    @Autowired
    private JwtUtils jwtUtil;
    
    @PostMapping("/login")
    public String login(@RequestBody LoginRequest request) {
        // 1. Chercher l'utilisateur par username
        // 2. Vérifier le password
        // 3. Générer et retourner le JWT
        return jwtUtil.generateToken(request.getUsername());
    }
    
    @PostMapping("/register")
    public User register(@RequestBody RegisterRequest request) {
        // 1. Créer nouvel utilisateur
        // 2. Hash le password
        // 3. Sauvegarder en BD
        // 4. Retourner l'utilisateur créé
        return authService.register(
            request.getUsername(),
            request.getEmail(),
            request.getPassword()
        );
    }
}

Annotations importantes:
- @RestController: Classe est un contrôleur qui retourne du JSON
- @RequestMapping("/auth"): Préfixe des URL = /auth
- @PostMapping: Accepte les requêtes POST
- @RequestBody: Convertit le JSON en objet Java
- @Autowired: Injection de dépendance


C) AuthService.java
────────────────────
Logique métier de l'authentification.

Responsabilités:
- Validation des données d'inscription
- Recherche d'utilisateur en BD
- Hash du password avec BCrypt
- Création d'utilisateur
- Vérification des identifiants

Code type:

@Service
public class AuthService {
    
    @Autowired
    private UserRepository userRepository;
    
    @Autowired
    private PasswordEncoder passwordEncoder;
    
    public User register(String username, String email, String password) {
        // 1. Vérifier si username/email existe déjà
        if (userRepository.findByUsername(username).isPresent()) {
            throw new RuntimeException("Username already exists");
        }
        
        // 2. Créer nouvel utilisateur
        User user = new User();
        user.setUsername(username);
        user.setEmail(email);
        // 3. Hash le password avec BCrypt
        user.setPassword(passwordEncoder.encode(password));
        
        // 4. Sauvegarder en BD
        return userRepository.save(user);
    }
}

Annotations:
- @Service: Classe service (logique métier)
- @Autowired: Injecter les dépendances

F) JwtUtils.java
──────────────────
Génération et validation des JWT tokens.

Responsabilités:
- Générer un JWT token avec le username
- Valider un token
- Extraire le username du token
- Gérer l'expiration du token

Code type:

@Component
public class JwtUtils {
    
    @Value("${jwt.secret:mySecretKey}")
    private String jwtSecret;
    
    @Value("${jwt.expiration:86400000}") // 24h en ms
    private int jwtExpirationMs;
    
    public String generateToken(String username) {
        return Jwts.builder()
            .subject(username)
            .issuedAt(new Date())
            .expiration(new Date((System.currentTimeMillis() + jwtExpirationMs)))
            .signWith(key())
            .compact();
    }
    
    public String getUserFromJwt(String token) {
        return Jwts.parserBuilder()
            .setSigningKey(key())
            .build()
            .parseClaimsJws(token)
            .getBody()
            .getSubject();
    }
    
    private Key key() {
        return Keys.hmacShaKeyFor(Decoders.BASE64.decode(jwtSecret));
    }
}

Format du JWT: header.payload.signature
- header: {"alg":"HS256"}
- payload: {"sub":"Djomino06","iat":1234567890,"exp":1234571490}
- signature: xxxxx (signé avec la clé secrète)


G) SecurityConfig.java
────────────────────────
Configuration de Spring Security et CORS.

IMPORTANT: Cette classe doit permettre CORS pour que le frontend accède à l'API.

Code type:

@Configuration
@EnableWebSecurity
public class SecurityConfig {
    
    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration configuration = new CorsConfiguration();
        // Permet les requêtes du frontend
        configuration.setAllowedOrigins(Arrays.asList("http://localhost:4200"));
        // Méthodes HTTP autorisées
        configuration.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        // Headers autorisés
        configuration.setAllowedHeaders(Arrays.asList("*"));
        // Inclure les credentials (cookies)
        configuration.setAllowCredentials(true);
        
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", configuration);
        return source;
    }
    
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            // Activer CORS
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))
            // Désactiver CSRF pour les APIs REST
            .csrf(csrf -> csrf.disable())
            // Mode stateless (pas de sessions)
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            // Autoriser tous les accès (pour l'instant)
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/**").permitAll()
                .anyRequest().authenticated()
            );
        
        return http.build();
    }
    
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

Configurations clés:
- CORS: Permet les requêtes cross-origin du frontend
- CSRF disable: Désactivé pour les APIs REST (pas nécessaire avec JWT)
- SessionCreationPolicy.STATELESS: Pas de sessions server (JWT au lieu)
- PasswordEncoder: BCrypt pour hasher les passwords

STRUCTURE JWT GÉNÉRÉ:
─────────────────────

Header (base64):
{
  "alg": "HS256"
}

Payload (base64):
{
  "sub": "Djomino06",           // Subject (username)
  "iat": 1698245000,             // Issued at (timestamp)
  "exp": 1698331400              // Expiration (timestamp)
}

Signature:
HMACSHA256(base64(header) + "." + base64(payload), "mySecretKey")

Format final:
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJEam9taW5vMDYiLCJpYXQiOjE2OTgyNDUwMDAsImV4cCI6MTY5ODMzMTQwMH0.ObQ2TFTizXHEFGb_L-7Pc4grEQcj6LIyPhiFGltYOFc

9. SÉCURITÉ ET CORS
===================

CONFIGURATION CORS:
────────────────────

SecurityConfig.java déjà configuré avec:
- Allowed Origins: http://localhost:4200 (frontend)
- Allowed Methods: GET, POST, PUT, DELETE, OPTIONS
- Allowed Headers: * (tous)
- Credentials: true

À MODIFIER AVANT PRODUCTION:
─────────────────────────────

configuration.setAllowedOrigins(Arrays.asList("http://localhost:4200"));
↓
configuration.setAllowedOrigins(Arrays.asList("https://votredomaine.com"));

Changer aussi:
- Le jwt.secret (clé très longue et aléatoire)
- Le jwt.expiration (actuellement 24h = 86400000ms)


HASHAGE DES PASSWORDS:
───────────────────────

Utilisé: BCrypt
- Chaque password est hasé avant sauvegarde en BD
- Non déchiffrable (one-way hashing)
- Résistant aux attaques brute-force
- Exemple: password123 → $2a$10$N9qo8uLOickgx2ZMRZoM...

Vérification:
passwordEncoder.matches(plaintextPassword, hashedPassword)


TOKENS JWT:
────────────

Stockage Frontend:
- localStorage["jwt_token"] = token
- ATTENTION: Clair en localStorage (pas sécurisé pour production)
- En production: utiliser httpOnly cookies

Validation:
- À chaque requête, le frontend inclut le token
- Le backend valide la signature et l'expiration
- Si invalid → 401 Unauthorized


10. DÉPANNAGE ET ERREURS COURANTES
===================================

ERREUR: "Connection refused" port 3306
─────────────────────────────────────
Cause: MySQL n'est pas démarré
Solution:
- Vérifier que MySQL est en cours d'exécution
- Sur Windows: Services → MySQL80
- Sur Mac: brew services start mysql
- Sur Linux: sudo systemctl start mysql


ERREUR: "Unknown database 'transcendence'"
──────────────────────────────────────────
Cause: BD non créée
Solution:
mysql -u root -p
CREATE DATABASE transcendence;


ERREUR: "Request method 'OPTIONS' not supported"
──────────────────────────────────────────────
Cause: CORS non configuré
Solution:
- Vérifier SecurityConfig.java
- Vérifier que corsConfigurationSource() est appelé
- Redémarrer le serveur


ERREUR: "Invalid JWT token" (du frontend)
──────────────────────────────────────────
Cause: Token expiré ou invalide
Solution:
- Vérifier que jwt.secret est le même partout
- Vérifier l'expiration du token
- Tester avec curl avant le frontend


ERREUR: "Could not find class 'JwtUtils'"
──────────────────────────────────────────
Cause: Dépendances manquantes
Solution:
mvn clean install
mvn dependency:resolve


ERREUR: BUILD FAILURE
──────────────────────
Cause: Erreurs de compilation
Solution:
1. Vérifier la syntaxe Java
2. Vérifier les imports
3. mvn clean install -X (verbose)
4. Consulter les warnings du build

12. CONVENTIONS DE CODAGE
==========================

NOMMAGE:
─────────

Classes:
- PascalCase: UserService, AuthController, JwtUtils
- Suffixes: *Service, *Controller, *Repository, *Request, *Response

Méthodes:
- camelCase: findByUsername, generateToken, validatePassword
- Verbes: get*, set*, find*, create*, update*, delete*, validate*

Variables:
- camelCase: userName, jwtToken, userRepository

Constantes:
- UPPER_SNAKE_CASE: JWT_SECRET, TOKEN_EXPIRATION_MS

──────────────

1. Importer les packages Spring en premier
2. Puis les imports métier
3. Puis java.*, javax.*

import org.springframework.stereotype.Service;
import org.springframework.beans.factory.annotation.Autowired;
import com.ft.transcendence.model.User;
import com.ft.transcendence.repository.UserRepository;
import java.util.Optional;

R: À développer - ajouter un filtre JWT dans SecurityConfig

Q: Où stocker les données sensibles?
R: application.properties.local (non commité) ou variables d'env

R: Consulter les logs dans la console / utiliser l'IDE debugger
